# TB-002 — EngineeringDataset Data Contract

**Document:** TB-002  
**Project:** MTDMS — Material Test Data Management System  
**Version:** 1.1  
**Status:** Approved / Frozen  
**Scope:** Output TXT file analysis only  
**Platform:** Excel 2019 VBA Add-in  
**Calculation model:** Array-based

---

## 1. Purpose

`EngineeringDataset` is the single source of truth for imported test data during runtime analysis.

The processing path is:

```text
TXT
 ↓
Parser
 ↓
Validation
 ↓
EngineeringDataset
 ↓
Calculation Engines
```

No calculation engine reads the TXT file directly.

---

## 2. File Information

```text
FileInfo
├── FullPath
├── FileName
├── FileSize
├── FileDate
├── FileHash
└── ImportTimestamp
```

The original TXT file is immutable. A file hash provides traceability when filenames are reused.

---

## 3. Authoritative Metadata

Only the following metadata fields are authoritative in the current file contract:

| TXT line | Source label | Internal field |
|---:|---|---|
| 10 | d/a | `DiameterOrArea` |
| 11 | b | `Width` |
| 13 | L0 | `InitialLength` |

All other metadata is ignored until explicitly approved.

The parser extracts the value; physical interpretation of `d/a` as diameter or area is handled later by specimen/configuration logic and is not guessed during import.

---

## 4. Raw Data

The data section contains:

```text
No
Time
Displacement
Deformationt
Force
```

Recommended runtime types:

| Array | Type | Unit |
|---|---|---|
| `No()` | Long | — |
| `Time()` | Double | source file time unit |
| `Displacement()` | Double | mm |
| `Deformationt()` | Double | mm |
| `Force()` | Double | kgf |

Raw values are preserved exactly as imported. No engineering conversion is performed by the file reader.

---

## 5. Index Alignment

All arrays share one point index.

For index `i`, the following values represent the same physical measurement point:

```text
No(i)
Time(i)
Displacement(i)
Deformationt(i)
Force(i)
EngineeringStress(i)
EngineeringStrain(i)
```

No calculation may reorder points independently of the master point index.

---

## 6. Point Count

`PointCount` is the authoritative number of imported data points.

Every active array must have exactly `PointCount` elements.

Points are not deleted during import. Invalid or excluded points are represented through status flags.

---

## 7. Derived Data

Derived arrays are generated by calculation engines and never overwrite raw arrays:

```text
DerivedData
├── EngineeringStress()
├── EngineeringStrain()
├── CorrectedStrain()
├── TrueStress()
└── TrueStrain()
```

Not every derived array is required to exist in every analysis.

---

## 8. Strain Source Model

The strain source is **segmented**, not a single global setting.

An individual test may use:

```text
Extensometer → Crosshead
```

The extensometer may be connected until the yield region and then released. After release, crosshead displacement becomes the strain source.

### Important distinction

The following are independent events:

```text
YieldPoint
≠
ExtensometerReleasePoint
≠
FracturePoint
```

The release point may occur before, at, or after the calculated/confirmed yield point.

---

## 9. Strain Segments

```text
StrainSegments()
├── Source
├── StartIndex
├── EndIndex
└── Status
```

The current minimum model supports at least:

```text
Segment 1: EXTENSOMETER
Segment 2: CROSSHEAD
```

`EngineeringStrain()` is assembled from these segments while preserving the original point indexes.

Automatic source switching is not assumed. The source-switch event must be explicitly detected or operator-confirmed according to the approved workflow.

---

## 10. Extensometer Status

The dataset must distinguish:

```text
NOT_SELECTED
SELECTED_VALID
SELECTED_INVALID
```

The existence of a `Deformationt` column, or a zero value in that column, does not by itself prove that an extensometer measurement is valid.

---

## 11. Events

The dataset maintains independent engineering events:

```text
Events
├── YieldPoint
├── ExtensometerReleasePoint
├── FracturePoint
└── GraphCorrectionEvents
```

Each event contains, conceptually:

```text
Event
├── Index
├── Time
├── Displacement
├── Force
├── Source
├── DetectionMethod
├── Confidence
└── OperatorConfirmed
```

Detection methods may include `AUTO`, `MANUAL`, and `LIBRARY_ASSISTED` where applicable.

---

## 12. Point Status

Points are never physically removed from the raw dataset. Status is assigned instead.

Examples:

```text
RAW
VALID
WARNING
INVALID
PRELOAD
ELASTIC
POST_YIELD
FRACTURE_CANDIDATE
POST_FRACTURE
EXCLUDED
```

These statuses are analytical classifications and do not modify raw values.

---

## 13. Operator Selection

```text
Selection
├── StrainSegments()
├── YieldPoint
├── ExtensometerReleasePoint
├── FracturePoint
├── SecondaryLength
├── RegressionWindow
└── GraphCorrection
```

The operator may manually confirm or modify relevant events through the Excel Ribbon workflow.

---

## 14. Validation

Validation is separated into two levels.

### Structural validation

Checks whether the file is parseable:

- file exists
- required metadata lines are accessible
- data header exists
- required columns exist
- data rows exist
- numeric fields can be parsed

### Engineering validation

Checks whether the parsed data is suitable for engineering calculation:

- `L0` is valid and positive
- required specimen dimensions are valid
- force data is usable
- sufficient data points exist
- selected extensometer data is valid when required
- source segments are logically defined

Validation result:

```text
Validation
├── IsStructurallyValid
├── IsEngineeringValid
├── ErrorCount
├── WarningCount
├── Errors()
└── Warnings()
```

---

## 15. Secondary Length

The original gauge length and post-fracture measured length are separate values:

```text
InitialLength (L0)
SecondaryLength (L2)
```

`L0` is read from TXT metadata line 13.

`L2` is entered/measured by the operator after fracture.

`L2` must never replace `L0`.

Conceptually:

```text
L0 = Original Gauge Length
L2 = Post-Fracture Measured Gauge Length
```

---

## 16. Post-Fracture Elongation

Post-fracture elongation is an independent result derived from `L0` and operator-measured `L2`:

```text
A% = ((L2 - L0) / L0) × 100
```

The result must preserve provenance:

```text
ElongationAfterFracture
├── L0
├── L2
├── Unit
├── MeasurementMethod = Manual
├── Operator
└── Timestamp
```

This post-fracture measurement is not assumed to equal the instantaneous strain value at the fracture point.

---

## 17. Graph Correction

Graph correction creates derived visualization data and never modifies raw data.

```text
RawData
 ↓
CalculatedData
 ↓
GraphCorrection
 ↓
CorrectedVisualizationData
```

The horizontal axis may be scaled using the operator-measured secondary length where required by the approved engineering method.

The correction must retain:

- raw strain
- calculated strain
- corrected strain
- scale factor
- correction method
- correction timestamp
- operator identity where applicable

---

## 18. Material Library Interaction

Material Library is a reference source, not test data and not a replacement for measured results.

It may be used during Graph Analysis/Correction for:

1. Young's modulus reference
2. Yield-region search guidance
3. Result plausibility checking

Example:

```text
Material Library
├── YoungModulusReference
├── YieldStrengthReference
└── Other approved material properties
```

Library values may create candidates, guidance, or warnings. They must not automatically overwrite the measured test result.

---

## 19. Young's Modulus

Young's modulus is calculated from the selected stress/strain region through the Regression Engine.

Conceptual flow:

```text
EngineeringStress()
        +
EngineeringStrain()
        ↓
RegressionEngine
        ↓
Slope / Intercept / R²
        ↓
YoungModulusEngine
```

The regression window is an explicit selection/provenance item.

---

## 20. Yield

Yield detection is independent from extensometer release.

Possible methods include:

```text
AUTO
MANUAL
LIBRARY_ASSISTED
```

The Material Library may help define a candidate/search region, but the library yield value does not automatically become the test yield result.

---

## 21. Fracture

Fracture is an independent event.

```text
Curve
 ↓
Candidate Detection
 ↓
Validation
 ↓
Operator Verification
 ↓
FracturePoint
```

Post-fracture points remain available in the dataset but may be marked `POST_FRACTURE` or `EXCLUDED` for calculations where appropriate.

---

## 22. Provenance

```text
Provenance
├── SourceFile
├── FileHash
├── ImportTimestamp
├── SoftwareVersion
├── CalculationVersion
├── SettingsVersion
├── Method
└── SessionID
```

Every important result must be traceable to the source dataset, calculation method, settings, and relevant event/selection indexes.

---

## 23. Result Provenance

A result should conceptually contain:

```text
Result
├── Value
├── Unit
├── Method
├── Source
├── InputRange
├── RegressionInformation
├── CalculationVersion
└── Provenance
```

For Young's modulus this includes at least the strain source/segments, regression start/end, slope, R², and calculation method.

---

## 24. Dataset State

Suggested lifecycle:

```text
IMPORTED
 ↓
STRUCTURALLY_VALIDATED
 ↓
ENGINEERING_VALIDATED
 ↓
READY_FOR_CALCULATION
 ↓
CALCULATED
 ↓
ANALYSIS_VERIFIED
 ↓
REPORT_READY
 ↓
ARCHIVED
```

Failure states may include:

```text
VALIDATION_ERROR
CALCULATION_ERROR
ANALYSIS_WARNING
```

A failed stage must not silently advance to the next stage.

---

## 25. Excel Boundary

The worksheet is a View, not the calculation source.

Forbidden runtime pattern:

```text
TXT → Worksheet → read cells → calculation
```

Required pattern:

```text
TXT → VBA Arrays → EngineeringDataset → Calculation
```

The worksheet is used for presentation, tables, reports, graph interaction, and Ribbon-driven workflow.

## 27. Approved Design Decisions

| ID | Decision |
|---|---|
| D-01 | YieldPoint and ExtensometerReleasePoint are independent events. |
| D-02 | Strain can be composed from multiple source segments. |
| D-03 | Each strain segment has its own source and index range. |
| D-04 | Material Library may be used during Graph Analysis/Correction. |
| D-05 | Material Library is reference/guidance and does not impose measured results. |
| D-06 | Graph Correction creates derived visualization data and never changes RawData. |
| D-07 | Yield may occur before, at, or after ExtensometerReleasePoint. |
| D-08 | All events remain traceable to the original dataset index. |
| D-09 | Horizontal graph axis may be scale-corrected. |
| D-10 | L0 comes from TXT metadata line 13. |
| D-11 | L2 is entered/measured by the operator after fracture. |
| D-12 | L2 never replaces L0. |
| D-13 | Post-fracture elongation is a separate auditable result. |
| D-14 | Corrected axis/strain is separate from raw/calculated strain. |
| D-15 | Material Library may provide modulus reference, yield guidance, and plausibility warnings. |
| D-16 | Worksheet is a View; runtime calculations are array-based. |
