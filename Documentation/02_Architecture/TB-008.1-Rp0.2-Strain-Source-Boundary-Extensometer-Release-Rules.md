# TB-008.1 — Rp0.2 Strain-Source Boundary & Extensometer Release Rules

**Document:** TB-008.1  
**Project:** MTDMS — Material Test Data Management System  
**Version:** 1.0  
**Status:** Approved / Frozen  
**Parent:** TB-008  
**Standard:** ISO 6892-1:2019  
**Scope:** Output TXT file analysis only  
**Calculation model:** Array-Based

## 1. Purpose

This document defines the handling of strain-source boundaries and Extensometer Release for the project's principal scenario:

```text
CROSSHEAD → EXTENSOMETER → CROSSHEAD
```

The specification applies only to analysis of exported TXT data. It does not control the machine, PLC, drive, or real-time acquisition.

## 2. Independent Events

The following remain independent:

```text
Yield Event
Rp0.2 Intersection
Extensometer Attach Event
Extensometer Release Event
Fracture Event
```

No event is inferred solely from another event.

## 3. Attach and Release

Two separate events are modeled:

```text
ExtensometerAttachEvent
ExtensometerReleaseEvent
```

Release is not inferred solely from `Deformationt = 0`.

## 4. Release Candidate

Automatic detection may produce:

```text
AUTO_CANDIDATE
```

A candidate is not a confirmed event. Manual confirmation produces:

```text
MANUAL_CONFIRMED
```

Manual rejection produces:

```text
MANUAL_REJECTED
```

## 5. Event Structures

### Attach

```text
ExtensometerAttachEvent
├── EventID
├── Index
├── Time
├── SourceBefore = CROSSHEAD
├── SourceAfter = EXTENSOMETER
├── DetectionMethod
├── Status
└── Provenance
```

### Release

```text
ExtensometerReleaseEvent
├── EventID
├── Index
├── Time
├── SourceBefore = EXTENSOMETER
├── SourceAfter = CROSSHEAD
├── DetectionMethod
├── Status
└── Provenance
```

## 6. Strain Source Segments

The dataset uses an explicit source map:

```text
StrainSourceMap()
```

Example:

```text
1–1000       CROSSHEAD
1001–2500    EXTENSOMETER
2501–5000    CROSSHEAD
```

Every sample index has exactly one active source.

## 7. Raw Data Retention

Release does not delete or overwrite either source:

```text
Crosshead()
Deformationt()
```

All raw arrays remain available for traceability and later analysis.

## 8. Rp0.2 Source Resolution

The source associated with an Rp0.2 result is determined from the intersection location.

Example:

```text
RpIndex = 1800
→ Source = EXTENSOMETER
```

and:

```text
RpIndex = 2800
→ Source = CROSSHEAD
```

The engine must not silently substitute another source.

## 9. Rp0.2 Before Release

If:

```text
Rp0.2Index < ReleaseIndex
```

and the Rp intersection lies within the Extensometer segment, the result is associated with Extensometer.

## 10. Rp0.2 After Release

If:

```text
Rp0.2Index > ReleaseIndex
```

and the Rp intersection lies within the resumed Crosshead segment, the result is associated with Crosshead.

## 11. Rp0.2 on a Boundary

If the exact intersection lies on a source boundary, the Dataset's explicit segment definition determines the source of that sample.

Example:

```text
1001–2500 = EXTENSOMETER
2501–5000 = CROSSHEAD
```

Therefore index 2500 belongs to Extensometer and index 2501 belongs to Crosshead.

## 12. Rp0.2 Between Two Different Sources

If the numerical intersection is between:

```text
2500 = EXTENSOMETER
2501 = CROSSHEAD
```

the result retains both source identities:

```text
LowerSource = EXTENSOMETER
UpperSource = CROSSHEAD
BoundaryCrossing = TRUE
```

The result may be assigned the status:

```text
SOURCE_BOUNDARY_CROSSING
```

and receives WARNING/VALID status only according to the approved method-specific validation rule.

## 13. Elastic Regression Across a Boundary

A single elastic regression must not silently combine different strain sources unless they are demonstrably expressed in a common valid strain coordinate system under the configured method.

If the elastic region crosses a source transition without a validated common basis:

```text
ElasticModulus.Status = WARNING
```

Graph Analysis may be required.

## 14. Source Comparison

When simultaneous data exists, MTDMS may calculate:

```text
Δε(i) = εEXT(i) - εCH(i)
```

This is an analysis array only. Raw values are never modified.

## 15. Manual Source Switch

Manual operator changes are stored as Events:

```text
ManualSourceSwitchEvent
├── EventID
├── Index
├── PreviousSource
├── NewSource
├── Reason
├── Operator
├── Timestamp
└── Comment
```

A manual switch changes the analysis source map, not the raw TXT dataset.

## 16. Event Priority

When multiple event candidates exist at the same location, confirmed manual information takes precedence over automatic candidates:

```text
MANUAL_CONFIRMED
        ↓
MANUAL_REJECTED
        ↓
AUTO_CANDIDATE
```

The original automatic candidate remains traceable.

## 17. Confidence

An automatic Release Candidate may contain a confidence value. Evidence may include:

```text
Deformationt behavior
Force behavior
Continuity
Crosshead/Extensometer comparison
Following segment stability
```

Confidence does not equal confirmation.

## 18. Yield and Release Ordering

All orderings remain valid Data Model states:

```text
YieldIndex < ReleaseIndex
ReleaseIndex < YieldIndex
YieldIndex ≈ ReleaseIndex
```

The software must not redefine one event to force a preferred ordering.

## 19. Rp0.2 and Release Ordering

Three principal states are supported:

### A — Rp before Release

```text
Rp0.2 < Release
```

Rp source is determined from the active segment at the intersection.

### B — Rp after Release

```text
Rp0.2 > Release
```

Rp source is normally Crosshead when the resumed Crosshead segment contains the intersection.

### C — Rp near/at Boundary

```text
Rp0.2 ≈ Release
```

The result retains boundary provenance and requires the configured validation rule.

## 20. Fracture

Release is not the end of the test dataset.

After Release:

```text
CROSSHEAD → Rm → FRACTURE
```

may continue.

## 21. Final Engineering Strain Array

The engine creates a calculated strain array using the source map:

```text
EngineeringStrain()
```

Conceptually:

```text
For each sample:
    if source = CROSSHEAD
        use Crosshead strain
    else if source = EXTENSOMETER
        use Extensometer strain
```

The raw arrays remain unchanged.

## 22. Rp0.2 Provenance

An Rp0.2 result retains the source boundary information:

```text
Rp0.2
├── LowerIndex
├── LowerSource
├── UpperIndex
├── UpperSource
├── BoundaryCrossing
├── ReleaseEventID
├── StrainSource
├── CalculationVersion
└── Provenance
```

## 23. Graph Analysis

Graph Analysis may display:

```text
Measured Curve
Crosshead Segment
Extensometer Segment
Crosshead Resumed Segment
Attach Event
Release Event
Yield Event
Rp0.2
Rm
Fracture
```

Verification markers are analysis aids and are not automatically included in the final report.

## 24. Graph Correction Separation

Source segmentation and graph correction are separate layers.

```text
Source Segmentation
        ↓
Calculated Strain
        ↓
Rp0.2 Calculation

Calculated Curve
        ↓
Graph Correction
        ↓
Corrected Visualization
```

Graph correction does not alter the source events or raw dataset.

## 25. Validation Matrix

| Condition | Rp0.2 handling | Source | Status |
|---|---|---|---|
| Rp before Release | Evaluate active segment | Segment source | Method-dependent |
| Rp after Release | Evaluate active segment | Usually Crosshead | Method-dependent |
| Rp exactly on boundary | Use explicit sample ownership | Boundary segment | Warning until rule validated |
| Rp between different sources | Preserve both boundary sources | Boundary Crossing | Warning/validation |
| Release candidate only | Candidate only | Current source retained | Candidate |
| Release confirmed | Update source map after event | Crosshead | Validatable |
| No valid Extensometer data | No Extensometer source | Crosshead | Extensometer unavailable |
| No Rp intersection | No numerical substitution | — | NOT_AVAILABLE |
