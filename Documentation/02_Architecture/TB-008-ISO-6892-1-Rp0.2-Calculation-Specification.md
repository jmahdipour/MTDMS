# TB-008 — ISO 6892-1 Proof Strength / Rp0.2 Calculation Specification

**Document:** TB-008  
**Project:** MTDMS — Material Test Data Management System  
**Version:** 1.0  
**Status:** Approved / Frozen  
**Standard:** ISO 6892-1:2019  
**Scope:** Output TXT file analysis only  
**Platform:** Excel 2019 VBA Add-in  
**Calculation model:** Array-Based

## 1. Purpose

TB-008 defines the MTDMS calculation contract for `Rp0.2`.

All calculations operate on arrays, not graph pixels.

```text
TXT
 ↓
Arrays
 ↓
Stress / Extension
 ↓
Elastic Line
 ↓
Offset Line
 ↓
Intersection
 ↓
Rp0.2
```

## 2. Input Arrays

Required/conditional arrays include:

```text
No()
Time()
Displacement()
Deformationt()
ForceRaw()
ForceN()
EngineeringStress()
EngineeringStrain()
StrainSource()
```

Geometry/configuration includes:

```text
A0
L0
Le
```

where `A0` is original cross-sectional area, `L0` is original gauge length, and `Le` is extensometer gauge length when applicable.

## 3. Raw Force

The source Force remains unchanged:

```text
ForceRaw(i) = kgf
```

SI calculation array:

```text
ForceN(i) = ForceRaw(i) × 9.80665
```

Raw and converted arrays remain separate.

## 4. Engineering Stress

```text
EngineeringStress(i) = ForceN(i) / A0
```

With N and mm², the result is MPa.

## 5. Extension and Strain

For an active extensometer source, where `Deformationt` represents extension:

```text
Extension(i) = Deformationt(i)
εEXT(i) = Extension(i) / Le
```

Extension and strain are distinct quantities.

```text
Extension ≠ Strain
```

## 6. Strain Source

The project default is:

```text
Initial Source = CROSSHEAD
```

The operator may switch to Extensometer. The Method Engine must consume the approved `StrainSource()` segmentation and must not silently substitute another source.

## 7. L0 vs Le

```text
L0 ≠ Le
```

They are retained as separate parameters. Proof-strength methodology must use the gauge-length definition applicable to the approved ISO 6892-1 implementation method.

## 8. Elastic Line

The elastic region is represented by a regression:

```text
σ = E × ε + b
```

Result structure:

```text
ElasticLine
├── E
├── b
├── StartIndex
├── EndIndex
├── R²
└── StrainSource
```

`b` is retained and is not silently forced to zero.

## 9. Rp0.2 Offset

For `Rp0.2`:

```text
Offset = 0.002
```

The offset line is parallel to the approved elastic line.

Conceptually:

```text
σoffset(ε) = E × (ε - 0.002) + b
```

The exact standard-specific construction and acceptance rules must follow the authorized ISO 6892-1:2019 implementation specification.

## 10. Material Library

Material Library may provide reference values such as expected modulus or yield information, but reference values must not silently replace measured test values.

Default calculation rule:

```text
E_Rp = E_measured
```

unless an explicitly configured graph-correction or method rule says otherwise.

## 11. Difference Array

For every valid point:

```text
Difference(i) = EngineeringStress(i) - OffsetStress(i)
```

The intersection is identified from this array rather than from a rendered graph.

## 12. Intersection Bracket

When the intersection lies between two samples:

```text
RpIntersection
├── LowerIndex
├── UpperIndex
├── LowerStrain
├── UpperStrain
├── LowerStress
├── UpperStress
├── LowerDifference
└── UpperDifference
```

## 13. Interpolation

The MTDMS implementation may linearly interpolate between the surrounding samples.

Given:

```text
D1 = Difference(i)
D2 = Difference(i+1)
```

implementation coefficient:

```text
α = D1 / (D1 - D2)
```

then:

```text
εRp = ε1 + α(ε2 - ε1)
σRp = σ1 + α(σ2 - σ1)
```

This interpolation is an MTDMS implementation decision and must not be described as a verbatim ISO requirement unless explicitly supported by the authorized standard text.

## 14. Force-Based Representation

Because the ISO proof-strength construction is expressed in terms of Force–Extension, the engine retains a Force/Extension representation in parallel with Stress/Strain:

```text
ForceN()
Extension()
```

Conceptual pipeline:

```text
Force
 ↓
Extension
 ↓
Elastic Line
 ↓
Offset Extension
 ↓
Intersection Force
 ↓
Rp = F / A0
```

```text
RpResult
```

## 16. Crosshead / Extensometer Boundary

The source segment at the Rp intersection is retained.

Example:

```text
1–1000      CROSSHEAD
1001–2500   EXTENSOMETER
2501–5000   CROSSHEAD
```

If Rp intersection is at index 1800:

```text
Rp0.2 Source = EXTENSOMETER
```

If at index 2800:

```text
Rp0.2 Source = CROSSHEAD
```

Any method-specific requirement for a valid extensometer at the Rp point is handled as validation; the engine must not silently substitute a different source.

## 17. Extensometer Release

Extensometer Release is an independent Event.

```text
Rp0.2 ≠ ExtensometerReleasePoint
```

A change such as `Deformationt → 0` may be an automatic release candidate but is not by itself proof of release.

## 18. Yield Results

`Rp0.2`, `ReH`, and `ReL` are independent result types and must not be conflated.

## 19. No Elastic Intersection

If no valid intersection exists:

```text
Rp0.2 = NOT_AVAILABLE
```

The engine must not use Max Stress, Last Stress, or another unrelated value as a substitute.

## 20. Multiple Intersections

The engine must support:

```text
Intersections()
SelectedIntersection
```

The selection rule must be explicit and method-configured. A simple first-crossing rule is not implicitly assumed.

## 21. Noisy Crossing

A single noisy sign transition must not automatically be treated as a valid proof-strength intersection. Local behavior and configured validation rules may be used to reject unstable crossings.

Exact numerical thresholds remain deferred until the authorized standard-specific implementation specification is established.

## 22. Manual Elastic Region

Operator review may adjust:

```text
ElasticStart
ElasticEnd
```

When changed, the engine recalculates `E`, the offset line, and Rp0.2. The operation is recorded as a manual analysis event.

Manual analysis means modifying the analysis region, not directly typing an Rp0.2 result.

## 23. Graph Representation

Verification graph may show:

```text
Measured Stress-Strain
Elastic Regression
Rp0.2 Offset Line
Rp0.2 Intersection
```

Verification lines/markers are analysis aids and are not automatically included in the final report.

## 24. Graph Correction Separation

Graph correction is a separate pipeline:

```text
CALCULATION
Raw → Stress/Strain → Rp0.2

GRAPH CORRECTION
Calculated Curve → CorrectedStrain()
```

Graph correction alone must not overwrite Rp0.2.

If corrected data is intended to affect a result, the ISO Method Engine must be explicitly rerun on the corrected dataset under a documented method version.

## 25. Validation

Minimum validation categories:

```text
A0 > 0
Required gauge length available
Valid elastic region
Valid offset
Valid intersection
Intersection within valid test range
Source segment valid
```

Possible result states:

```text
VALID
WARNING
INVALID
NOT_AVAILABLE
MANUAL
```

## 26. Provenance

Every Rp0.2 result retains:

```text
├── E
├── b

├── UpperIndex

```

## 27. Freeze Rules

| ID | Decision |
|---|---|
| D-99 | Rp0.2 is calculated entirely from arrays. |
| D-100 | Force/Extension and Stress/Strain representations remain traceable. |
| D-101 | Rp0.2 offset is 0.002 strain. |
| D-102 | Offset line is parallel to the approved elastic line. |
| D-103 | Offset slope equals the approved elastic slope. |
| D-104 | Measured E is the default slope for Rp calculation. |
| D-105 | Material Library E does not silently replace measured E. |
| D-106 | A0 is used to convert proof force to proof stress. |
| D-107 | Intersection is found from arrays, not graph pixels. |
| D-108 | Intersection may be between two samples. |
| D-109 | Linear interpolation is an MTDMS implementation decision unless the authorized standard text specifies otherwise. |
| D-110 | Multiple intersections are detectable. |
| D-111 | No intersection produces no fabricated Rp0.2 result. |
| D-112 | Rp0.2, ReH and ReL are separate results. |
| D-113 | Rp0.2 is independent of the Extensometer Release Event. |
| D-114 | Graph Correction alone does not change Rp0.2. |
| D-115 | Manual correction modifies the analysis region and triggers recalculation. |
| D-116 | Raw and calculated arrays are never overwritten. |
| D-117 | Every Rp0.2 result has provenance. |

## 28. Deferred Rules

The following are not frozen here without the authorized ISO 6892-1:2019 implementation text:

- exact elastic-region selection limits;
- universal R² threshold;
- exact interpolation requirement if specified differently by the standard;
- exact local noise rejection threshold;
- detailed source-validity rules at the proof-strength intersection;
- detailed tolerances and acceptance criteria.
