# TB-020 — ISO 6892-1 Curve Boundary, Necking/Rm Region & Post-Rm Data Handling Specification

**Document:** TB-020  
**Project:** MTDMS — Material Test Data Management System  
**Version:** 1.0  
**Status:** Approved / Frozen  
**Parent:** TB-009 → TB-019  
**Scope:** Output TXT file analysis only  
**Platform:** Excel 2019 VBA Add-in  
**Calculation model:** Array-Based

## 1. Purpose

TB-020 defines handling of the engineering stress–strain region after Rm. Rm is an important result/boundary, but it is not the automatic end of the test curve. Post-Rm data remains available for necking/fracture analysis and audit until the applicable terminal/fracture boundary.

## 2. Independent Concepts

```text
Elastic → Yield/Plastic → Uniform Plastic Deformation → Rm → Necking/Post-Rm → Fracture
```

Rm, Post-Rm Region and Fracture are independent concepts.

## 3. Rm Index

`RmIndex` identifies the DatasetIndex of the maximum valid Engineering Stress under the applicable Method and valid-region rules.

```text
Rm = Maximum(EngineeringStress)
```

## 4. Rm Is Not a Device Event

Rm is a Result/Boundary and not necessarily an Event generated by the testing machine.

## 5. Rm vs Fracture

`RmIndex` and `FractureIndex` are independent. In a normal tensile test, Rm will generally precede fracture, but the software must not assume equality.

## 6. Post-Rm Region

Rows after Rm and before the applicable fracture/terminal boundary are classified as `PostRmRegion` and retained in the analytical dataset.

## 7. No Automatic Post-Rm Deletion

The following rule is prohibited:

```text
Curve = Data up to Rm
```

unless a specific Rm-Limited View is requested.

## 8. Necking Candidate

Post-Rm points may receive `NeckingCandidateFlag=True`, but reduction in Engineering Stress alone does not prove physical necking. A confirmed necking status requires an appropriate Method/Analysis rule.

## 9. Rm Point Metadata

```text
RmPoint
├── DatasetIndex
├── Stress
├── Strain
├── Time
├── Source
└── SegmentID
```

## 10. Strain Source at Rm

The Rm point may originate from either Extensometer or Crosshead depending on TB-018 source segmentation. TB-020 never changes the source.

## 11. Source Transition

The approved project scenario may contain:

```text
EXTENSOMETER → release → CROSSHEAD
```

and Rm may therefore legitimately use Crosshead strain.

## 12. Engineering Stress After Rm

A decrease in Engineering Stress after Rm does not make the Stress value invalid. Validity is governed by the Dataset/Method eligibility rules.

## 13. Force After Rm

A reduction in Force after Rm is not, by itself, a fracture event or invalid-data condition.

## 14. Fracture Boundary

TB-009 determines `FractureIndex`. TB-020 consumes that boundary and does not independently redefine fracture.

## 15. Post-Fracture Data

Rows after fracture remain in Raw Dataset and remain traceable. They may be excluded from the engineering test curve according to the applicable Method/terminal-boundary rule.

## 16. Fracture Is Not Zero Force

```text
Force = 0 → Fracture
```

is not an approved rule.

## 17. Fracture Is Not Minimum Force

```text
Minimum Force → Fracture
```

is not an approved rule.

## 18. Curve Terminal Index

`CurveTerminalIndex` is an explicit analytical boundary. It may equal FractureIndex when the applicable Method specifies this, but the equality must not be assumed silently.

## 19. Rm-Limited View

Two independent derived views are supported:

```text
FullEngineeringCurve
RmLimitedCurve
```

where:

```text
RmLimitedCurve = Data[Start : RmIndex]
```

The FullEngineeringCurve remains the principal complete engineering curve.

## 20. Full Curve Uses

FullEngineeringCurve supports:

- complete test visualization
- Post-Rm/necking review
- fracture review
- audit
- data-quality investigation

## 21. Rm-Limited View Uses

RmLimitedCurve supports Method/Analysis views that intentionally restrict display or analysis to the region ending at Rm.

## 22. Post-Rm Flags

Every valid point after Rm and before the applicable fracture/terminal boundary may contain:

```text
PostRmFlag
NeckingCandidateFlag
```

`NeckingConfirmed` must not be set merely because Stress decreases.

## 23. Rm Plateau

If multiple adjacent points satisfy the configured Rm-equality/tolerance rule, the system records:

```text
RmPlateauFlag
RmCandidateCount
RmSelectionRule
```

The selection of the reported Rm point must be deterministic and auditable.

## 24. Rm Selection Rule

If multiple points share the maximum valid Stress within the configured tolerance, the applicable Method Configuration explicitly determines whether the first, last or another defined candidate is selected.

## 25. Noise

Noise must not be treated as an automatic reason to delete Post-Rm data. Any specific noise-handling rule belongs to a separate Method/Analysis layer.

## 26. No Smoothing

TB-020 does not smooth the curve.

## 27. No Resampling

TB-020 does not resample the original measurement series.

## 28. No Interpolation

Interpolation is not performed unless explicitly authorized by the applicable Method.

## 29. No Extrapolation

TB-020 never generates points outside the original Dataset.

## 30. Dataset Integrity

After Rm, the following remain aligned by DatasetIndex:

```text
DatasetIndex
Stress
Strain
Time
Force
Source
SegmentID
```

## 31. Graph Boundary

The complete graph conceptually represents:

```text
Start → Yield → Rm → Necking/Post-Rm → Fracture
```

## 32. Operator Markers

Operator-analysis markers may include:

```text
Yield
Rp0.2
Rm
Fracture
```

These are Analysis UI artifacts and are not automatically included in the final report.

## 33. Graph Correction

Graph correction is separate from calculation data. If horizontal-axis correction is required:

```text
CalculationStrain
GraphCorrectedStrain
```

remain separate. Calculation Strain is never overwritten by Graph Correction.

## 34. Post-Fracture Elongation

TB-010 determines post-fracture gauge-length measurement and elongation after fracture. TB-020 does not infer post-fracture gauge length from the stress–strain curve.

## 35. Report Views

The reporting layer may support:

```text
FULL_CURVE
RM_LIMITED
FULL_CURVE_WITH_MARKERS
```

according to configuration and reporting requirements.

## 36. Raw Export

A complete/raw export preserves Post-Rm and Post-Fracture rows. A limited export may intentionally restrict the exported analytical view, but must identify that it is limited.

## 37. Audit Requirements

Rm must remain traceable through:

```text
RmIndex
RmStress
RmStrain
RmSource
RmSegmentID
RmSelectionRule
```

to the original TXT DatasetIndex/row.

## 38. Traceability Example

```text
Rm
 ↓
RmIndex = 1542
 ↓
DatasetIndex = 1542
 ↓
Stress / Strain
 ↓
Source = CROSSHEAD
SegmentID = 3
 ↓
Original TXT Row 1542
```

## 39. Dependency Chain

```text
TB-018 EngineeringStrain
          ↓
TB-019 ValidCurveDataset
          ↓
TB-020 Rm / Post-Rm Boundary
          ↓
TB-009 Fracture Boundary
          ↓
TB-010 Post-Fracture Elongation
```

## 40. Architectural Principle

TB-020 classifies, bounds, flags and traces data. It does not delete data merely to make the curve visually cleaner.
